# ServicePro — 31.10.2026 barqarorlik tuzatishlari

Bu nusxa **ServicePro(8).zip** asosida tayyorlandi. Mavjud billing, abonentlar,
chatlar, arizalar tarixi va ma’lumotlar bazasidagi yozuvlar o‘chirilmagan.

## Kiritilgan o‘zgarishlar

1. Splash sahifasi: majburiy 1,8 soniya kutish 350 ms qilindi; avval profil
   aniqlanadi, qolgan ro‘yxatlar fon rejimida yuklanadi. Sekin aloqa uchun
   8 soniyalik boshlang‘ich kutish chegarasi qo‘yildi. Splash animatsiyasi
   bir marta bajariladi, uzluksiz grafik qayta chizish yo‘q.
2. Telefon: ariza yaratish tugmasi shaffof pastki paneldan tepaga chiqarildi.
   Ro‘yxatning pastki qismi ham panel bilan yopilmaydi.
3. Telefon/planshet: bo‘limlar orasida chap/o‘ng tez surish qo‘shildi;
   mavjud 175 ms yumshoq animatsiya va tab holatlari saqlangan.
4. Arizalarga biriktirilgan videolar endi ilovaning o‘zida ochiladi.
   Umumiy media oynasida video faqat foydalanuvchi bosganda yuklana boshlaydi.
5. Vazifa dalillari va reklama videolari endi 80 MB gacha fayllarni operativ
   xotiraga birdan o‘qimay, lokal fayldan yuklaydi. Tanlangan videoni
   yuborishdan oldin ko‘rish imkoniyati qo‘shildi.
6. Windows desktop uchun `video_player_win: 3.2.2` qo‘shildi. Video ilovaning
   ichida o‘ynaydi, lekin konkret video kodeki Windows’da mavjud bo‘lishi shart.
7. Vazifalar sahifasi qayta ochilganda ro‘yxat yangilanadi; xatolik ko‘rinsa
   **Qayta urinish** tugmasi chiqadi.

## Juda muhim: «Vazifalar va hisobotlar» SQL sozlamasi

Ushbu funksiya Supabase'da quyidagilarga tayanadi:
`work_items`, `work_item_events`, `work-evidence` bucket va `work_*` RPC.
ZIP ichida **`supabase/WORK_ACTIVITY_ADS_SETUP.sql`** mavjud.

**Agar bu SQL avval o‘rnatilmagan bo‘lsa, faqat Flutter kodini almashtirish
bilan «Vazifalar» ishlamaydi.**

1. Supabase ma’lumotlar bazasining zaxirasini oling.
2. Sinov (staging) loyihasida mavjud migratsiyalardan keyin
   `supabase/WORK_ACTIVITY_ADS_SETUP.sql` ni SQL Editor orqali bajaring.
3. Direktor bilan ishchining bitta tashkilotga biriktirilganini tekshiring.
4. Testda topshiriq yaratish → ishchi dalil bilan yuborish → direktor tasdiqlash
   ketma-ketligini sinang.
5. Ishlasa, keyin asosiy bazada qo‘llang. Skript jonli bazangizga bu yerda
   avtomatik qo‘llanmagan.

Supabase Free tarifida bitta faylning global limiti **50 MB**; ilovadagi 60/80 MB
limitli videolar faqat Storage sozlamalari va tarif ruxsat bersa yuklanadi.
Katta videoda 413 xato chiqsa 50 MB dan kichikroq MP4 sinang.

## O‘rnatish va tekshirish

1. Amaldagi ServicePro papkasini zaxiralang; `.env`, imzolash kalitlari va
   Windows Firebase SDK keshi mavjud loyihada saqlansin.
2. Shu ZIPdagi yangilangan `lib/`, `test/`, `pubspec.yaml` ni joylang;
   `supabase/WORK_ACTIVITY_ADS_SETUP.sql` ham loyiha ichida qolsin.
3. Bir marta `flutter pub get` ishga tushiring — yangi Windows media plagini
   lockfile va platform pluginlarini yangilashi kerak.
4. `flutter analyze` va `flutter test` ni ishga tushiring.
5. Telefon va Windows’da videoni tanlash/yuborish/ichki player, shaffof nav,
   ariza tugmasi, surish, vazifa-hisobot va oldingi chat funksiyalarini sinang.

**Cheklov:** Bu muhitda Flutter/Dart SDK, Windows compiler va jonli Supabase
ulanishi yo‘q. Shu sabab real mobil/Windows build, widget testlar va SQLning
production ishlashi shu yerda tasdiqlanmagan; ularni o‘z qurilmangizda
tekshirishingiz kerak.

## 31.10.2026 — `flutter analyze` va widget-test logidagi xatolar

Taqdim etilgan terminal logida `flutter analyze` 156 ta warning/info bergan,
`flutter test` esa 2 ta testda to‘xtagan. Quyidagi kod tuzatishlari kiritildi:

1. Mehmonning katta ekrandagi yon paneli Material rang qatlamiga o‘tkazildi;
   `ServicePro` sarlavhasi uzunligi kichik ekranda sig‘adi (RenderFlex overflow fix).
2. Profil dialogi testi endi `ListView` ostidagi *kech quriladigan* theme
   dropdownini oldin aylantirib topadi; asosiy Navigator o‘zgarmaydi.
3. `AppState.forTesting` Supabase bilan ulanmaganini tekshirib, testdagi
   tashkilotlar ro‘yxati uchun asossiz RPC chaqiruvini yubormaydi.
4. Eski `withOpacity` chaqiruvlari `withValues(alpha: ...)`ga,
   `MaterialStatePropertyAll` `WidgetStatePropertyAll`ga, eski dropdown va radio
   konstruktori yangi Flutter APIlariga moslashtirildi.
5. Keraksiz null tekshiruvlari, sinfdan tashqari `notifyListeners` chaqiruvi,
   ishlatilmaydigan eski billing klassi va ko‘rsatilgan qolgan lintlar ko‘rib
   chiqildi. Hali qo‘llanishi mumkin bo‘lgan xususiy yordamchi metodlar
   yo‘qotilmadi.

Windows PowerShell’da **loyiha ildizida**:

```powershell
flutter pub get
flutter analyze
flutter test
```

Ushbu muhitda Flutter SDK yo‘qligi sabab yangilangan kodga nisbatan bu
uchta buyruqni bu yerda bajarib, `0 issues` / `All tests passed` natijasini
mustaqil tasdiqlab bo‘lmadi. Agar qurilmangizda boshqa versiyaga xos yangi
xabar qolsa, yangi logni yuboring — uning aniq satri asosida tuzatiladi.

## Android build: Gradle va NDK (31.10.2026)

Android ilovani ishga tushirishda chiqqan ikkita versiya ogohlantirishi uchun:

- `android/gradle/wrapper/gradle-wrapper.properties`: Gradle `8.13` dan
  xavfsiz tuzatishlar bilan chiqarilgan `8.14.3` ga ko‘tarildi.
- `android/app/build.gradle.kts`: `ndkVersion = "28.2.13676358"` qo‘shildi,
  chunki `jni` plaginiga shu versiya talab qilingan.

Windows Android Studio → SDK Manager → SDK Tools → **Show Package Details** →
**NDK (Side by side)** ichidan **28.2.13676358** o‘rnatilsin. Gradle wrapper
birinchi buildda yangi Gradle distributivini internetdan yuklaydi.

**Kotlin ogohlantirishi:** Loyiha hozir AGP `8.11.1` va Kotlin `2.2.20` ishlatadi.
Flutter yangi built-in Kotlin migratsiyasini AGP `9+` uchun ko‘rsatmoqda.
`file_picker`, `image_picker_android` va boshqa tashqi plaginlar hali KGP
ishlatayotgan bo‘lishi mumkin. Ularni majburan avtomatik migratsiya
qilmadik: kod logikasi va Play Market buildiga xavf tug‘dirishi mumkin.
`android.builtInKotlin=false` va `android.newDsl=false` saqlandi.

Ushbu o‘zgarishlar Android Gradle build jarayoniga tegishli; Windows Firebase
C++ linkerining `LNK4099` warninglariga aloqasi yo‘q.
